# 09 · 其他架构与工程改进：知道它们在整体中做什么

> 状态：精简版已完成  
> 深度：了解 · 不单独深入  
> 论文定位：第 1、12–14、18、37 页

## 本篇只回答一个问题

4-bit Floating Point Main Key-Value Cache（FP4 Main KV Cache，4 位浮点主全局键值缓存）、DSpark、Engram 和 Single-Pass manifold-constrained Hyper-Connections（Single-Pass mHC）在 V4.1 中分别做什么，哪些结论需要留下？

这四项不是理解 Causal Encoder-Decoder（CED）、Compressed Sparse Attention 2（CSA2）和 Sliding-Window Attention Bounded Replay（SWA Bounded Replay）的前置。本篇只保留它们在 V4.1 中的作用、关键改动和收益口径。

## 1. FP4 Main KV Cache：继续压缩已经留下的全局缓存

CSA2 解决“多层为什么要重复保存全局 KV”；FP4 继续解决“必须保存的那份 Main KV 能否用更少字节表示”。

DeepSeek-V4 已对 Indexer Q/K 使用 FP4 Quantization-Aware Training（QAT，量化感知训练）。V4.1 在后训练中进一步对 **Main KV Cache** 加入 QAT：

- Main KV 以 FP4 保存，Attention 前再反量化。这里的直接收益是缓存容量和搬运量减少，不是直接执行 FP4 Attention 矩阵乘法。
- 使用 E2M1 数值和每 16 个 channel 共享的 E4M3 scale，省略 NVFP4 的第二级 global scale。
- 在 Rotary Position Embedding（RoPE，旋转位置编码）之后量化，以避免 Decode 时的额外处理。
- 对量化更敏感的 SWA KV 仍使用 FP8。因此“FP4 KV”不代表模型的所有 KV 或所有计算都变成 FP4。

报告结果中，FP4 使 Main KV 相对 FP8 的存储量接近减半。它与 CSA2 跨层共享共同得到下面的全局缓存数字：

| 报告数字 | 表示什么 | 不能解读为 |
|---|---|---|
| 约 890 bytes/token | 每个历史 token 的 Global KV Cache 占用，这部分始终在 High Bandwidth Memory（HBM，高带宽显存） | 整个请求或整个模型只占 890 bytes/token |
| 约为 V4-Flash 的 1/4 | CSA2 跨层共享与 FP4 Main KV 的组合收益 | CSA2 或 FP4 单独将总显存降为 1/4 |
| Persistent KV 约为 V4-Flash 的 1/8 | 全局 KV 压缩，再加上不再长期保存 SWA KV 的组合收益 | 运行时总内存、磁盘或端到端成本都降为 1/8 |

这部分没有一篇被报告引用的“DeepSeek FP4 Main KV”独立论文。报告借鉴了 MXFP4 和 NVFP4 等数值格式，而将 FP4 扩展到 Main KV 及上述取舍是 V4.1 的具体设计。

## 2. DSpark：加速 Decode 和 Agent rollout

DSpark 有独立论文。它属于投机解码：轻量 Draft 模块先提出多个候选 token，主模型再并行验证，从而减少逐 token 调用主模型的次数。

V4.1 报告额外给出了具体集成方式：

- Draft 模块有 3 个 Transformer block，SWA window 为 128；
- 一次前向并行计算 5 个候选位置；
- Markov Head 补充候选 token 之间的依赖；
- Confidence Head 估计各位置被接受的概率，调度器再结合当前引擎吞吐曲线，动态决定验证长度；
- Backbone 预训练完成后才单独训练 DSpark，此时冻结 Backbone；
- 后训练时继续训练 DSpark，但 DSpark objective 不向 Backbone 回传梯度。

它既用于在线生成，也用于 Reinforcement Learning（RL，强化学习）和 On-Policy Distillation（OPD，同策略蒸馏）的 rollout。对 Agent 最需要记住的是：**DSpark 主要加速模型输出和训练样本生成，不会缩短工具本身的执行时间。**

V4.1 也不再在 Backbone 预训练期间使用 Multi-Token Prediction（MTP，多 token 预测），而是在 Backbone 训练后引入 DSpark。

## 3. Engram：用条件查表扩展模型记忆容量

Engram 有独立论文。它根据 token n-gram 做确定性哈希寻址，只读取少量匹配的 Embedding，再通过上下文门控与 Transformer 隐藏状态融合。它的目标是让一部分事实记忆由稀疏查表承担，避免记忆容量和每 token 计算量一起增长。

V4.1 沿用原设计的 tokenizer compression、multi-head hashing、context-aware gating 和 multi-branch integration，同时作了两项修改：

1. 删除 short causal convolution，因为收益不足以抵消对推理系统的复杂度。
2. Engram Embedding 使用 momentum-based update 加 Sinkhorn balancing，以减少大规模表参数的优化器状态开销。

报告中的落地配置为 196B Engram 参数，平分到两个模块；使用 2、3、4-gram 和 8 个 hash head，模块放在从 0 计数的第 1 层和第 14 层。确定性寻址使系统可以通过 Remote Direct Memory Access（RDMA，远程直接内存访问）从主机内存预取数据，并与 Transformer 计算重叠。RL rollout 时则将 Engram Table 驻留在 GPU，减少主机内存压力和碎片导致的 Out of Memory（OOM，内存不足）。

Engram 不是 KV Cache、Retrieval-Augmented Generation（RAG，检索增强生成）或 Agent 的跨任务长期记忆；它是训练在模型内、按输入 token 稀疏访问的参数化记忆表。

## 4. Single-Pass mHC：为内核融合改写层间依赖

原始 mHC 有独立论文，但 **Single-Pass mHC 和 Mega-mHC 是 V4.1 报告明确提出的升级**。

mHC 在 Transformer block 之间维持多路残差流。原设计中，当前 block 要用当前隐藏状态预测的系数 `A_l` 进行输入混合。计算 `A_l` 需要先完成对全部 hidden dimension 的 reduction，因此后续混合必须等待，很难在一次数据读取中完成。

Single-Pass mHC 让当前 block 使用前一个 block 已经生成的 `A_(l-1)`：

$$
A_l X_l \quad\longrightarrow\quad A_{l-1}X_l
$$

这个错开一层的改动解除了当前数据依赖。部署时，Mega-mHC 可将残差更新、输入混合、下一层系数预测、pre-norm 和 FP8 转换融合到一个 Kernel 中。

报告给出的局部激活访存口径是：

$$
(4n+4)d \quad\longrightarrow\quad (2n+2)d
$$

即相对 DeepSeek-V4 原始多 Kernel 实现减半，并达到该数据路径的理论下界。报告称错开一层使用系数的性能下降可忽略。这是 **mHC 模块的激活数据流量减半**，不是整个模型的显存、计算量或端到端延迟减半。

## 5. 放回整体架构

| 机制 | 主要处理的问题 | 与 Agent 的关系 |
|---|---|---|
| CED | 长输入的 Prefill 计算 | 历史不断增长时，降低新输入处理成本 |
| CSA2 + FP4 Main KV | 全局历史的缓存容量和搬运 | 降低长任务历史常驻 HBM 的压力 |
| SWA Bounded Replay | 局部状态的持久存储 | 任务暂停后用有限重算恢复执行 |
| DSpark | Decode 吞吐 | 加速 Agent 回答生成和训练 rollout |
| Engram | 模型内部的参数化记忆容量 | 增强知识存储，不代替 Agent 外部记忆 |
| Single-Pass mHC | 残差混合的激活访存 | 属于底层部署效率改进 |

## 需要记住的四句话

1. FP4 Main KV 完成了全局缓存收益的闭环，但 SWA KV 仍使用 FP8。
2. DSpark 加速生成和 rollout，与降低 Prefill 成本的 CED 分工不同。
3. Engram 是模型内部的稀疏参数化查表记忆，不是 Agent 的外部长期记忆。
4. 原始 mHC 有独立论文，但 Single-Pass 依赖改造和 Mega-mHC 是本报告值得留下的新内容。
