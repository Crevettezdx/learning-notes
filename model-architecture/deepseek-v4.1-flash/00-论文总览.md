# 00 · 论文总览：为长任务 Agent 重组计算与记忆

> 状态：已完成  
> 深度：总览 · 必读  
> 来源：报告第 4–8、37 页；具体机制另见各篇所列章节

## 这篇报告研究什么

Key-Value Cache（KV Cache，键值缓存）保存模型后续生成时需要读取的历史状态。《DeepSeek-V4.1-Flash: Pushing the Limits of KV Cache Compression》研究的是：**如何降低长上下文 Agent 的输入计算、历史缓存和状态搬运成本，同时保持较强的任务能力。**

它讨论的模型是 V4.1-Flash。报告给出的配置包括 552B 主干参数，另有 196B Engram 参数；支持图像与文本输入、自回归文本输出，以及最长 1M token 上下文。

这些是模型规模和支持范围。它们不直接代表某个 Agent 任务的成功率、时延或部署成本。

## 为什么从 Agent 的工作方式出发

解释示例：一个编程 Agent 先读取需求与代码，再运行工具、接收日志、修改文件并验证。任务反复推进，历史输入不断增长。

模型为此承担几种成本：

1. 处理新增输入，建立可供生成使用的状态。
2. 保留历史表示，并从大量历史中寻找当前相关内容。
3. 生成下一段输出。
4. 在任务恢复或缓存缺失时，重新加载或重建必要状态。

因此，优化长任务不能只看输出速度。模型如何处理输入、组织历史、恢复状态，同样决定任务能否经济地持续运行。

## 核心架构的分工

| 问题 | 机制 | 核心变化 | 笔记 |
|---|---|---|---|
| 大量输入通过整个网络，prefill 昂贵 | Causal Encoder-Decoder（CED，因果编码器-解码器） | 解码器全局 KV 从编码器最终输出投影，大部分输入只运行前半网络 | [04](04-CED.md) |
| 多层重复保存全局历史和执行检索 | Compressed Sparse Attention 2（CSA2，压缩稀疏注意力 2） | 跨层共享全局 KV，并可复用 Top-K 检索结果 | [05](05-CSA2.md) |
| 剩余索引器扫描长历史仍然昂贵 | 分层稀疏索引 | 解码器后续索引器在共享候选池内检索 | [06](06-分层稀疏索引.md) |
| 隐藏状态与两类KV关系容易混淆 | Encoder状态与KV缓存 | 说明SWA KV、Main KV怎样从隐藏状态产生和流动 | [07](07-Encoder状态与KV缓存.md) |
| 局部状态保存或精确重建昂贵 | Sliding-Window Attention Bounded Replay（SWA Bounded Replay，滑动窗口注意力有界回放） | 回放最近一个窗口，近似重建局部状态 | [08](08-SWA有界回放.md) |
| 仍需保存的全局缓存占用容量 | 4-bit Floating Point KV（FP4 KV，4 位浮点键值缓存） | 降低主要全局 KV 的存储精度 | [09](09-其他架构与工程改进.md) |
| 长输出生成占用时间 | DSpark | 生成草稿并验证，用置信度帮助安排验证长度 | [09](09-其他架构与工程改进.md) |
| 模型知识容量与每 token 计算量绑定 | Engram | 用稀疏访问的参数化查表记忆扩展容量 | [09](09-其他架构与工程改进.md) |
| 多路残差混合带来较多激活读写 | Single-Pass manifold-constrained Hyper-Connections（mHC） | 错开一层使用混合系数，解除内核融合的依赖 | [09](09-其他架构与工程改进.md) |

理解这张表需要两个前置概念：[Agent 推理成本](01-Agent工作负载与推理成本.md)和[局部与全局注意力](02-局部与全局注意力.md)。

CED 和 CSA2 分别回答“历史状态从哪里产生”和“不同层如何共享与使用历史状态”；分层索引进一步减少检索工作；有界回放补齐局部状态，连接模型结构与实际部署。FP4、DSpark、Engram 和 Single-Pass mHC 统一放在[09-其他架构与工程改进](09-其他架构与工程改进.md)中速读。

## 为什么称为新架构

模型仍属于 Mixture-of-Experts（MoE，混合专家）Transformer。结构上的新意主要体现在：

- **计算路径重组**：40 层分成 20 层因果编码器与 20 层解码器，长输入与新 token 生成采用不同的计算路径。
- **跨层状态共享**：一些层生成全局 KV，一些层复用 KV 后重新检索，另一些层连检索结果也一起复用。
- **历史访问方式改变**：保留局部细节，同时通过稀疏选择访问全局历史，并限制后续索引的搜索范围。

有界回放、低精度缓存和内核优化使这些结构能高效部署。架构与系统协同是报告的重要特点，但部署策略与后训练方法仍应和网络结构区分。

报告也说明了对既有工作的继承，例如 CED 受到 You Only Cache Once（YoCo）启发。这里的“新”指实质的结构改进与组合设计，不意味着所有组件都首次出现。

## 需要记住的结果与口径

以下均为报告结果：

| 数字 | 含义 | 不能由此直接推导 |
|---|---|---|
| prefill 8B、decode 16B | 每 token 激活参数口径；长输入主体的计算路径不同 | 整个模型只有 8B/16B 参数，或端到端耗时严格减半 |
| 全局 KV 约 890 字节/token，约为 V4-Flash 的 1/4 | 全局缓存占用更小 | 总显存、总成本都下降到 1/4 |
| 持久 KV 约为 V4-Flash 的 1/8 | 压缩全局缓存与取消 SWA 长期持久缓存的共同收益 | 全部内存或磁盘用量都下降到 1/8 |
| 最长 1M token 上下文 | 模型支持的上下文范围 | 每条远距离证据都能被可靠找到 |

两点会贯穿后续学习：

- 稀疏选择可能遗漏信息；有界回放采用近似状态。报告称已测场景质量影响很小，同时承认未充分刻画的边界仍需测试。
- 能力提升还来自预训练数据、任务环境、RL 与蒸馏。报告明确没有提出新的后训练算法，不能把整体分数变化全部归因于新架构。
