# 模板快照如何生成

[返回目录](./README.md) · [术语速查](./glossary.md)

> 本页问题：要从运行中继续执行，必须事先保存哪些状态？

快照保存运行状态，供后续实例恢复；模板构建仍需先完成一次冷启动。

![冷启动与快照恢复逐阶段对照](./assets/snapshot-restore-optimization-map.png)

本页关注图中的模板准备与状态保存；请求到来后的处理见[恢复过程](./09-snapshot-restore.md)。

## 先完整启动，再保存状态

```text
准备镜像和 VM 配置
        ↓
完整冷启动一次模板 VM
        ↓
等待应用健康检查成功
        ↓
暂停 vCPU
        ↓
保存 Ready 时刻的运行状态
```

模板构建仍需支付一次完整冷启动成本，但后续实例可以重复使用结果。

## 需要配套保存的状态

- **Guest RAM**：程序堆栈、缓存、内核数据结构等内存内容。
- **vCPU 寄存器**：CPU 执行上下文，包括继续执行的位置。
- **虚拟设备状态**：虚拟磁盘、网卡及设备队列等状态。
- **RootFS / 磁盘状态**：与内存状态一致的系统文件和写入结果，由存储与平台配套管理。

只有磁盘快照不够：缺少内存与 CPU 执行点时，程序仍需走开机和初始化流程。

模板用于克隆新实例时，还需在恢复阶段处理身份、凭据、随机数和连接状态。
