# 预热池与快照：速度、成本和扩展能力

[返回目录](./README.md) · [术语速查](./glossary.md)

> 本页问题：为什么预热池命中可能更快，而快照更适合复用和突发扩展？

## 两种机制各自准备什么

- **预热池**：提前准备完整可用实例；请求时主要完成领取与绑定，因此命中延迟通常更低，但闲置实例占用资源。
- **快照恢复**：提前准备可复用的运行状态；请求时仍需恢复实例，但不必为每个潜在请求长期维持一个 Ready VM。

## “上限更高”具体指什么

一个预热池有 N 个 Ready 实例，在来不及补池的短时间窗口里，能直接承接的请求数受 N 限制。扩大这一储备，需要维持更多闲置实例。

模板快照不会被领取掉，同一份模板可以持续创建新实例。它通常能以更低的待机成本支持模板复用和按需扩展，但仍受节点容量、真实内存、I/O、网络资源和恢复吞吐限制。

因此，“快照上限更高”主要讨论**成本与扩展弹性**，不意味着单次请求必然更快，也不是任意实现下的固定结论。

## 选择时看什么

- 更关注最低命中延迟：保留一定数量的预热实例。
- 更关注模板复用和突发扩展：评估快照恢复。
- 两者都需要：组合使用，并测量池耗尽后的恢复吞吐。
