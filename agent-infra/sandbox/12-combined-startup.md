# 如何组合预热池、快照与冷启动

[返回目录](./README.md) · [术语速查](./glossary.md)

> 本页问题：如何兼顾日常低延迟和突发流量？

一种可选的三级启动策略：

```text
请求到达
   ├─ 有 Ready 实例可领 → 直接领取
   ├─ 无 Ready 实例，有可用快照 → 从快照恢复
   └─ 无可用快照 → 完整冷启动
```

## 三条路径的分工

- **预热池**：服务可以直接命中的请求，降低请求时延。
- **快照恢复**：承接池外请求，也可用于快速补池。
- **完整冷启动**：构建模板，或在镜像、配置不适用现有快照时提供启动路径。

这是一种组合设计，不代表所有项目默认提供。平台需要把调度、资源预置、恢复、Ready 检查和异步补池串起来。

节点完全没有剩余容量时，仍需等待或扩容；快照不会消除资源不足。
