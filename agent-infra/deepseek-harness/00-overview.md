# 第 0 单元｜论文总览：让系统在运行中改变组成

[返回目录](README.md) · [下一篇：动态组合需要同时管理依赖与影响](01-dynamic-composition.md)

插件系统和 agent harness 往往需要长期运行，同时不断增删工具、替换服务、调整配置。重启整个进程可以重新组装系统，却也会中断工作、丢失进程内状态。论文关心的是：能否在组件粒度完成这些变化，让未受影响的部分继续运行？

难题来自两个方向：组件撤出时，需要收回它对共享环境的可逆改变；组件依赖的能力变化时，需要协调相关组件的运行。论文分别称之为**时间可组合性**和**空间可组合性**。

作者借用 effect 和 coeffect 描述“改变环境”与“依赖环境”，并将它们变成运行时机制：为可逆改变保存撤销动作，持续检查声明的依赖是否满足，再把两者放进统一的运行环境中协调。

但单个组件能够正确运行和退出，还不足以保证多个组件交错加载、卸载时仍然成立。论文因此建立组件生命周期模型，处理加载、清理、异步和失败等过程，并在模型条件下证明整个系统的可组合性。

这些思想落地为 **Cordis**：它管理 effect 和依赖，并支持声明式配置及热重载，使组件可以在运行中调整。论文以 **Koishi** 为正式应用案例；自演化 agent harness 是后续验证方向。本系列以论文为主线，用 DSH 源码辅助观察这些思想如何落地。

后续依次学习：**动态组合的难题 → 时间可组合性 → 空间可组合性 → 两者协同 → DSH 应用与边界**。
