asyncio：协程怎样运行、暂停，再被唤醒？

Python 3.11 · macOS 默认 SelectorEventLoop · 默认 Task 调度方式。按 ①—⑥ 阅读主链；蓝线表示事件完成后的唤醒路径。

把代码对应到图上

await f()：通常在当前 Task 内驱动子协程；不会自动创建另一个 Task。

asyncio.create_task(f())：在已有运行中的循环里创建 Task，默认安排首次推进回调。循环本身不会因此新建。

await 已完成对象：可能立即继续；await asyncio.sleep(0)：主动让出执行机会。

asyncio.sleep(1)：注册定时器；到期回调完成 Future，然后唤醒等待它的 Task。

取消、阻塞与外围管理

task.cancel()：请求取消，通常同时取消正在等待的 Future；Task 恢复时收到 CancelledError。只有异常传出才成为已取消。

asyncio.timeout()：用定时回调请求取消当前 Task；退出该超时上下文时按规则转换为 TimeoutError。

TaskGroup 管任务生命周期；Lock / Event / Semaphore / Queue 用各自的等待者集合协调任务，等待者通常是 Future。

同步阻塞代码会卡住循环，连超时回调也不能及时运行。to_thread() 移走阻塞工作，但取消等待无法强制终止线程。

对象关系：Coroutine 是可暂停的执行过程；Task 驱动 Coroutine，同时也是可等待结果；Future 连接结果与唤醒。图中省略 TaskGroup、进程池与锁的内部细节，以保持主链清晰。中文使用系统字体，无外部资源。
