# 事件循环、Task 与 Future 如何协作

## 核心问题

调用一个异步函数后，协程何时真正执行？它在 `await` 时为何不会持续占用 CPU，又是谁在等待条件满足后让它继续运行？

## 主链

1. `async def f()` 只定义协程函数；调用 `f()` 创建协程对象，但还没有执行函数体。
2. `asyncio.run()` 创建事件循环和入口 `Task`，并把首次推进回调放入就绪队列。
3. 事件循环执行回调，`Task` 驱动协程，直到返回、抛出异常，或 `await` 一个尚未完成的 `Future`。
4. 等待期间，协程保存暂停位置并让出事件循环；I/O 由操作系统处理，定时器和跨线程通知也在循环外等待条件。
5. 条件满足后，相应回调为 `Future` 设置结果或异常；`Future` 再把 `Task` 的唤醒回调加入就绪队列。
6. 事件循环下一次执行该回调时，`Task` 才从暂停位置继续。

## 三个关键对象

- `Coroutine`：可暂停、可恢复的执行过程。
- `Task`：驱动协程执行，同时提供一个可等待的最终结果。
- `Future`：连接“结果尚未产生”和“结果完成后唤醒等待者”。

## 两个重要边界

- 同步阻塞代码会卡住事件循环，使其他任务和超时回调都无法准时运行。`asyncio.to_thread()` 可以移走阻塞工作，但取消等待不能强制终止线程。
- `task.cancel()` 是协作式取消请求。只有 `CancelledError` 最终从协程传播出去，`Task` 才进入已取消终态；本地取消也不代表外部副作用已撤销。
